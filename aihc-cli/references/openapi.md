# OpenAPI 透传

仅当当前 CLI 原生子命令未覆盖用户需求时使用。`aihc curl` 自动处理 BCE V1 签名；不自行实现鉴权，也不把真实凭证写入 URL、请求头或示例文件。

## 流程

1. 用相关命令组帮助确认缺少能力。
2. 从官方 API 参考核实 action/路径、API 版本、HTTP 方法、必填字段、分页和返回结构。未核实时不猜接口名称。
3. 继承本次操作选定的配置和地域。优先使用官方支持的相对路径；完整 URL 必须核实为对应官方服务地址。
4. 区分只读与变更操作，并保持用户授权范围。查询故障不能成为自动调用写接口的理由。
5. 检查业务响应中的成功/错误字段和请求 ID，不能只检查 HTTP 状态码。异步操作仍需查询资源状态。

```bash
aihc curl --help
# 官方文档提供的数据集列表查询示例
aihc curl '/?action=DescribeDatasets&pageSize=10&pageNumber=1' \
  -X GET -H 'version: v2'
```

执行前核实该 API 当前版本和参数，按需追加已确定的 `-C`。带 `&` 的 URL 必须整体引用。复杂 JSON 先在本地构造并校验，再作为单个参数传给 `--data`；不假设 `aihc curl` 支持原生 curl 的全部选项或 `@文件` 语法。

创建请求结果不明确时，按业务唯一特征查询再决定下一步；不自动重放写请求。对外报告请求 ID 和脱敏错误，不公开签名头或完整敏感响应。
